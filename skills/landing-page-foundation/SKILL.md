# Landing Page Architecture

## Purpose
Transform a vague landing page brief into a sharp page structure with clear narrative flow, section priority and decision logic.

This skill exists to prevent generic LPs that look visually acceptable but fail to make a coherent argument.

## Core Principle
A landing page is a sales argument expressed through interface. The structure must earn attention, explain value, remove friction and direct the user toward one primary action.

## When To Use
- At the start of a new LP project.
- When the offer exists but the page structure is still unclear.
- When the page has too many sections and needs simplification.
- When design is moving faster than strategic clarity.
- When a hero section looks polished but the rest of the page has no narrative logic.

## Inputs Expected
- Product, service or offer description.
- Audience definition.
- Traffic source if known.
- Primary conversion goal.
- Constraints such as deadline, stack, visual references or performance limits.

## Output Required
- A recommended section sequence.
- A short explanation of why each section ex ists.
- A primary CTA and any supporting CTA roles.
- A list of what should be removed, deferred or treated as optional.
- Open questions that block accuracy.

## Workflow
1. Clarify the single conversion action.
2. Define the audience's awareness level.
3. Identify the page's strongest promise.
4. List the main objections preventing action.
5. Build a section order that answers those objections progressively.
6. Remove sections that do not increase clarity, trust or conversion intent.

## Recommended Baseline Structure
1. Hero
2. Problem or tension
3. Solution or mechanism
4. Benefits or outcomes
5. Proof or credibility
6. Offer details
7. FAQ or objection handling
8. Final CTA

This order is a baseline, not a law. Reorder only when there is a strategic reason.

## Decision Rules
- Do not add a section only because "most LPs have it".
- Avoid duplicate sections that restate the same claim in different language.
- If trust is the main problem, move proof earlier.
- If confusion is the main problem, explain the mechanism earlier.
- If the offer is emotionally driven, strengthen aspiration before technical detail.
- If the offer is rational or operational, reduce abstraction and explain specifics sooner.

## Anti-Generic Standards
- Every section must answer one concrete question from the visitor.
- Every section must have a single job.
- Every transition between sections should feel intentional, not decorative.
- Never use placeholder sections such as "Features", "Why choose us" or "About" unless they have precise strategic function.

## Deliverable Format
Use this structure when applying the skill:

```md
# LP Architecture

## Conversion Goal

## Audience

## Main Promise

## Objections

## Section Order
1. ...
2. ...

## Notes Per Section

## What To Exclude

## Open Questions
```
